# MANAFORGE — Magic: The Gathering, played against an AI

A browser implementation of Wizards of the Coast's **Magic: The Gathering**, 1v1 against a
computer opponent. Ninth in a series. **Private and local** (PLAN.md D1): no remote, no deploy.
The handoff that started it is `../../HANDOFF.md` in the owner's MANAFORGE folder; `PLAN.md`
owns every decision and the dated Status.

## The regime — decided, not to be re-litigated

**This is a reproduction, and fidelity is the product.** A divergence from the rules is a defect
to fix, never a design choice.

1. **Wizards owns the rules.** `docs/rules.md` is a citation index into the **Comprehensive
   Rules effective September 25, 2026**, kept in gitignored `scratch/rules/`. Every engine rule
   names the section it implements in a comment: `// CR 704.5g`. When a card and the engine
   disagree, read the rule and fix the engine.
2. **Wizards owns balance.** There is no `BALANCE.md`. Printed numbers are never tuned.
3. **Oracle text on the face, verbatim.** Not the printed ink of an old printing. Reminder text
   is display-only: stripped before compiling, kept on the face.
4. **Nothing playable contains content that does not work correctly.** A card the compiler
   cannot read in full is `un`, and validation refuses it from any registered deck;
   `data/defects.js` hides a card that misbehaves.
5. **1v1 against the AI**, 20 life, London mulligan.

## The hard rules

1. **No build step.** Plain browser JS, IIFEs on one `window.MF` namespace, script order declared
   in `index.html` with a `<!-- ui -->` marker. Runs from `file://` and `node tools/serve.mjs`.
2. **The engine surface is exactly `legalActions(s)` / `apply(s, action)` / `isTerminal(s)`**,
   plus `whoActs(s)`. `apply` deep-copies. Never mutate a state in place.
3. **Every UI affordance derives from `legalActions`; every number shown comes from the engine**
   (`MF.chars` for power, toughness, types, colours and abilities; `MF.costOf`; `MF.whyNot`).
4. **One queue of invocations is the control flow.** An effect runs on a copy; a question
   discards the partial run and the answer re-runs it. A pending head owns the game.
5. **Priority is CR 117.** State-based actions (CR 704) are checked, then triggers go on the stack
   in APNAP order (CR 603.3b), then a player receives priority. All pass in succession: the top
   of the stack resolves, or the step ends.
6. **One door per rule:**
   - `MF.ask` — every choice. No auto-take path.
   - the cost door (`payCost`) — total cost (CR 601.2f), mana abilities inside payment (CR 605.3b).
   - the damage door (`MF.dealDamage`) — prevention, lifelink, deathtouch, combat or not.
   - the zone-move door (`MF.move`) — enters / dies / leaves replacements; a new object (CR 400.7).
   - the characteristics door (`MF.chars`) — the layer system (CR 613). Nobody reads a printed
     power, toughness, type or ability directly.
   - the stack — every spell and every non-mana ability.
7. **Targets are chosen on announcement (CR 601.2c) and re-checked on resolution (CR 608.2b).**
8. **Cards are data, compiled from Oracle text** by `tools/build-cards.mjs`, a grammar, not a list
   of cards. Every pattern is anchored to the whole sentence. New op = handler + compiler pattern
   + describer; `tools/audit-cards.mjs` diffs the description against the Oracle text.
9. **Seeded RNG; every shuffle and random choice happens inside `apply`.**
10. **No silent fallbacks.** Neither `if (!MF.x)` nor `MF.x || {}`. A missing dependency throws.
11. **NEVER ASSUME A CHOICE.** One option or fifty, the player is asked: a target, a payment, a
    land to tap, an order. Not asked, because not a choice: "this", "all of", indistinguishable
    objects (identical basic lands), and a window with nothing legal in it.
12. **OPEN INFORMATION IS A RULE.** Every public zone has a viewer; everything revealed, milled,
    discarded, sacrificed, destroyed, exiled or countered is named in the log. The opponent's
    hand and both libraries show counts only.
13. **Every prompt says what it is about**: the source card, the target, the numbers, and what
    declining does, with the numbers on the buttons.
14. **Verify in the real browser.** Every UI commit says what was checked on the real page.
15. **Playable first.** Tests protect a working build; they are not the product.

## Registers

| File | Holds |
|---|---|
| `PLAN.md` | every decision, with a dated Status. No other file states one. |
| `DEVIATIONS.md` | rules the engine does not yet keep, each naming its CR section |
| `TODO.md` | wanted improvements to things that already work |
| `data/defects.js` | cards that do not behave as they read — hidden from the player |

## Layout

```
index.html                 the entry point; its script list is the load order
js/                        ns, engine, ops, ai, then the interface
data/cards.js decks.js     GENERATED by tools/build-cards.mjs — never edit by hand
data/defects.js            the gate
tools/                     all .mjs, no dependencies (Node 24)
tests/                     one file per area; each test named for the card or CR section
docs/rules.md rights.md sources.md takedown.md
scratch/                   gitignored: rules text, MTGJSON files, sandboxes
```

## This machine

Windows. The Bash tool is Git Bash; `/tmp` there is not visible to `node`, so scratch files go
under `scratch/`. `gh` is not installed. The repo lives under OneDrive.
